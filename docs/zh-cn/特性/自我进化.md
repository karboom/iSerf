# 自我进化

iSerf 的**自我进化**特性允许智能体在运行时根据错误反馈自主修复和优化工具代码，实现持续进化。

## 核心概念

### iFunction

iFunction 是支持自我进化的工具类型，采用目录结构管理多版本代码：

```
iFunction/
├── echarts/                    # 工具名称（驼峰命名）
│   ├── info.json               # 工具配置，指定当前版本
│   └── fallback/               # 版本目录
│       ├── info.json           # 版本说明
│       ├── Echarts.java        # 工具实现
│       └── Echarts.class       # 编译后的类文件
```

### 目录结构

- **一级子目录**：工具名称（驼峰命名，如 `echarts`）
- **二级子目录**：版本名称（如 `fallback`）
- **info.json**：记录当前引用的版本和工具说明

## 工作原理

### 1. 工具调用与错误捕获

当 Agent 调用 iFunction 工具时：

```java
// Agent 内部逻辑
switch (matchedTool.getType()) {
    case Tool.TYPE.IFUNCTION:
        try {
            var functionPath = getIFunctionPath(matchedTool);
            var cls = (FunctionWrapper) CodeUtil.load(versionDir, functionPath.get(2));
            result = handleToolCallResult(cls.run(call.arguments));
        } catch (Exception e) {
            result.setError("Error calling IFunction: " + e.getMessage());
        }
        break;
}
```

### 2. 错误类型处理

工具调用返回以下格式的结果：

```json
{
    "direct": {},    // 直接返回给用户
    "error": "",     // 触发自我进化
    "llm": ""        // 返回给 LLM 继续处理
}
```

当返回 `error` 时，触发自我进化流程。

### 3. 自我进化流程

```
┌─────────────────┐
│  工具调用失败   │
│  返回 error     │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 收集输入参数    │
│ 和错误信息      │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 调用 LLM 生成    │
│ 修复后的代码    │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 编译、加载并    │
│ 测试新代码      │
└────────┬────────┘
         │
    ┌────┴────┐
    │  成功？ │
    └────┬────┘
     是  │   │ 否
       ▼   ▼
  ┌─────────┐  ┌─────────────┐
  │ 继续执行 │  │ 达到最大重试 │
  └─────────┘  │ 次数？       │
               └──────┬──────┘
                   是 │   │ 否
                     ▼   ▼
              ┌───────────┐  ┌─────────────┐
              │ 抛出异常  │  │ 递归重试    │
              └───────────┘  └─────────────┘
```

## 自我进化实现

Agent 内部的 `updateToolWithRetry` 方法实现自我进化：

1. **读取当前代码**：从本地文件系统读取 Java 源文件
2. **构建提示词**：包含输入参数、错误信息和当前代码
3. **调用 LLM**：生成修复后的代码
4. **编译测试**：使用 `CodeUtil.compile` 编译并 `CodeUtil.load` 加载
5. **递归重试**：失败时增加重试计数，直到达到 `maxEvoRetry`

```java
private Mono<Void> updateToolWithRetry(Item.ToolCall toolCall, Integer attempt) {
    // 读取当前代码
    var currentCode = Files.readString(javaFile.toPath(), StandardCharsets.UTF_8);
    
    // 构建提示词
    var prompt = "请根据以下错误信息更新代码:\n\n输入参数：\n\n%s\n\n错误信息：%s\n\n当前代码:\n%s\n\n 请修改 runner 里面的逻辑，仅需要告诉我最终的代码，不要带 markdown 标记"
            .formatted(toolCall.arguments.toString(), toolCall.getResult().toString(), currentCode);
    
    // 调用 LLM 生成新代码
    return llm.send(List.of(userMessage), null, null)
            .reduce("", (acc, chunk) -> acc + chunk.getChoices().get(0).getText())
            .flatMap(updatedCode -> {
                try {
                    // 编译、加载和运行
                    CodeUtil.compile(updatedCode, targetDir);
                    var obj = CodeUtil.load(targetDir, className);
                    if (obj instanceof FunctionWrapper wrapper) {
                        wrapper.run(toolCall.arguments);
                    }
                    return Mono.empty();
                } catch (Exception e) {
                    if (attempt >= maxEvoRetry) {
                        throw new RuntimeException("Max attempts reached");
                    }
                    return updateToolWithRetry(toolCall, attempt + 1);
                }
            });
}
```

## 最佳实践

### 1. 版本管理

- 使用有意义的版本名称（如 `fallback`、`v1`、`optimized`）
- 保留历史版本以便回滚
- 定期清理过时的版本

### 2. 错误处理

- 在工具实现中返回结构化的错误信息
- 使用 `error` 字段触发自我进化
- 使用 `llm` 字段让 LLM 决定下一步操作

### 3. 提示词优化

- 提供清晰的错误描述
- 包含完整的输入参数
- 说明期望的行为

### 4. 编译优化

- 使用虚拟线程加速编译过程
- 为每个版本创建独立的编译目录
- 缓存已编译的类文件
