# 集群说明

提供一个支持弹性伸缩的集群服务，每个节点既提供服务，也充当路由。外层通过负载均衡来统一入口。不同节点之间通过消息总线实现数据转发和订阅，通过元数据中心维护集群运行状态。

## 架构说明

核心类：`ContainerServer` 统一承载协议无关的元数据管理和消息总线逻辑，`AgentLifecycle`（抽象类）管理 Agent 生命周期，`TeamLifecycle`（抽象类）管理 Team 生命周期，通过 `addTransport()` 挂载多个 `ITransport` 实现（如 `WebsocketTransport`、`MqttTransport`、`DingtalkTransport`），各 transport 将客户端事件委托给 ContainerServer 统一处理。

等效节点的好处是可以利用现成的负载均衡器，客户端只需要连接一个地址，对集群内部的伸缩无感。
采用消息总线进行通信解耦，有效降低大规模节点通信资源消耗，并且提供通信的可靠性。

依据 Agent 驻留内存的特点，类比现实世界：

- 扩容 = 新盖办公楼，新的客户引导至新的办公区
- 节点 = 办公区，客户来了，相关的智能体都来这里办公
- 消息总线 = 网线，类似于远程办公支持

## 用户侧协议

客户端与服务端通信采用 `{msgId, body}` 结构包裹请求和响应数据：

- **请求**: `{"msgId":"<唯一请求ID>","body":{...具体参数}}`
- **成功响应**: `{"msgId":"<对应请求ID>","body":{"data":{...}}}`
- **错误响应**: `{"msgId":"","body":{"error":"错误信息"}}`

### 支持的事件

| 事件 | 说明 |
|------|------|
| `agent.activate` | 从持久化存储加载 Agent 到内存 |
| `agent.deactivate` | 将 Agent 从内存移除回持久化存储 |
| `agent.create` | 创建 Agent |
| `agent.send` | 向 Agent 发送消息 |
| `agent.subscribe` | 订阅 Agent 消息流 |
| `agent.unsubscribe` | 取消订阅 Agent |
| `agent.toolCall` | 调用 Agent 工具缓存 |
| `agent.list` | 查询 Agent 列表 |
| `agent.edit` | 编辑 Agent |
| `agent.detail` | 获取 Agent 详情 |
| `team.create` | 创建 Team |
| `team.list` | 查询 Team 列表 |
| `team.remove` | 删除 Team |
| `team.edit` | 编辑 Team |
| `team.detail` | 获取 Team 详情 |

详细协议说明见 [Socket.IO 客户端](SocketIO客户端.md)。

## 元数据

| 项目 | 说明 |
|------|------|
| 节点信息 | 集群中所有节点的列表（id、ip、port） |
| Agent 驻留节点 | Agent 所在的节点 ID |

### Redis 存储

优势：响应速度快，并发高

劣势：集群情况下仅提供最终一致性

适用场景：中小规模集群，对一致性要求不苛刻的场景

## 消息总线

| 主题 | 说明 | 消息结构 |
|------|------|------|
| `{nodeId}-message` | 节点间通信 | JSON 数组：`["sourceNodeId", "type", "event", "body"]` |

### 消息类型

| type | 说明 | 流转方向 |
|------|------|----------|
| `proxy` | 将用户事件代理转发到目标节点 | 源节点 → 目标节点 |
| `reverse` | 将处理结果反向推回源节点 | 目标节点 → 源节点 |

### Pulsar

优势：高吞吐量、低延迟、支持持久化存储、消息可追溯、支持多租户、水平扩展能力强

劣势：架构相对复杂、运维成本较高、资源占用较大

适用场景：大规模集群，对可靠性和吞吐量要求高的生产环境

## 弹性伸缩

### 扩容流程

1. 新增服务器节点
2. 新节点注册到元数据中心
3. 负载均衡器发现新节点并分配连接
4. 新用户在新节点就地创建 Agent
5. 正常工作

### 缩容流程

1. 目标节点设置 `isShuttingDown = true`
2. AuthListener 阻塞新连接，Nginx 超时后自动切换到其他节点
3. 调用 `stop()` 从元数据移除节点，停止所有 transport
4. 受影响的 Agent 在现有节点重新唤醒
5. 正常工作

## C10M 问题

### 资源消耗

- **内存消耗**: 每个 Agent 驻留内存，需合理规划堆大小和 GC 策略
- **连接消耗**: Socket.IO 长连接 + MessageBus 订阅连接
- **线程消耗**: Socket.IO 事件线程 + MessageBus 消费线程

### 可用性

- 节点无状态（Agent 元数据存储在外部），故障时可快速恢复
- 优雅停机 + Nginx 配合实现无中断滚动更新
- 消息总线（如 Pulsar）提供消息持久化和可靠投递

### 性能

- 本地 Agent 访问无网络开销
- 跨节点通信仅经过一次 MessageBus 转发
- Agent 列表查询支持多节点异步聚合

### 可维护

- `ContainerServer` + `AgentLifecycle` + `TeamLifecycle` + 接口 `ITransport` 分离协议无关逻辑
- 新增传输协议只需实现 `ITransport` 接口
- 元数据和消息总线均可替换实现（只需实现 `IMetaData` / `IMessageBus` 接口）
